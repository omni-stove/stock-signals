# 強制フロー戦略メモ — 他プレイヤーの「強制的な売買」を先回りする

> 「追証売りみたいなやつ」= 自分の意思ではなく、ルール・制度・資金繰りによって**機械的に出てくる売買フロー**を狙う発想。
> 価格が割安/割高だから動くのではなく、「**売らざるを得ない人 / 買い戻さざるを得ない人**」がいるから動く。ここに歪みが生まれ、利益機会になる。
>
> 対象: 日本株（東証）/ 現watchlist は半導体（285A キオクシア・6857 アドバンテスト・6920 レーザーテック・6981 村田）。
> このメモはアイデア整理のみ。コード変更なし。

---

## 0. 大原則

強制フローには方向性がある。**踏まされる側の損失 = 反対側の利益**。

| 強制フロー | 出る向き | 自分の取り方 |
|---|---|---|
| 追証・ロスカット売り | 売り（投げ） | 投げ切ったところを**買う**（リバ取り） |
| 踏み上げ（買い戻し） | 買い（カバー） | 火がつく前に**買う** / 過熱を**売る** |
| インデックスリバランス | 引け成行（両向き） | 数日前に**仕込み**、当日引けに渡す |
| SQ・オプション期日 | ピン留め/反動 | 張り付き解放後の方向に乗る |

重要なのは「歪みは一時的」という点。強制フローが**出尽くした瞬間**が最大のエッジ。出る前に逆張りで突っ込むのは轢かれる。

## 1. 追証・ロスカット売り（最重要・このwatchlistで一番効く）

### メカニズム
信用買いが膨らんだ銘柄が急落 → 評価損拡大 → 追証発生 → 期日までに入金できない口座が**強制決済（投げ）**。
半導体は値動きが荒く（高ATR）レバ買いが集中しやすいため、この現象が起きやすい王道セクター。

### 取れるデータで作る「投げ警戒スコア」
| シグナル | 使うフィールド | 解釈 |
|---|---|---|
| 信用買い残が厚い | `margin.long_qty`, `margin.ratio`（信用倍率） | 倍率が高い＝買い方の含み損が出ると投げが連鎖しやすい |
| 直近で買い残が急増 | `margin.long_chg`（WoW増減） | 高値掴みの新規買いが積み上がった直後の急落は危険＝投げ燃料 |
| 価格が買い方の平均建値を割る | `daily.ma25_dev_pct`, `daily.ma5_dev_pct`, `daily.close` vs `ma25` | MA25大幅下方乖離＝多くの買い方が含み損 |
| 値動きが荒い | `daily.atr_pct`, `daily.atr_vs_baseline` | ATR急拡大＝追証ラインに一気に届く |
| 投げの最終局面 | `daily.vol_x_20d`（出来高倍率）, `daily.rsi_14` | 出来高急増＋RSI極端低下＝セリングクライマックスの兆候 |

### 狙い方（買い場の取り方）
1. **事前に警戒**: 信用倍率高 × long_chg急増 × 上昇後 の銘柄をマーク。「投げ予備軍」。
2. **トリガー**: SOX急落などで地合いが崩れ、その銘柄がMA25を割って加速下落。
3. **エントリー**: 出来高が平常の数倍に膨らみ（`vol_x_20d`高）、RSIが売られすぎ、下ヒゲ＝**投げ尽くし**を確認してから買う。
4. **追証期日効果**: 追証は発生日から数営業日で強制決済。「急落から2〜3営業日後の寄り〜前場」に最後の投げが出やすい → そこが底になりやすい。

### 注意
- `回転日数`・`逆日歩`は**取れない**ので、投げの切迫度は WoW増減＋乖離率で代用。
- 落ちるナイフを掴まない。**出尽くし確認が必須**。

## 1b. ロスカット売りスコア — 具体設計（ロング/ショート両対応）

### なぜ「一日N%下落」だけでは不十分か
ロスカットの本質は**下落幅そのものではなく「含み損の信用買い方がどれだけいるか × そこに追証が出るか」**。
同じ -7% でも、信用買い残スカスカ・下げ続きの銘柄は投げる燃料がなく、ただの売りで終わる。
信用倍率高・直近で買い残急増した高値圏の銘柄こそ追証連鎖が着火する。
→ **「下落 × 投げ燃料」の積**で見る。N%は引き金（着火）の一要素にすぎない。

さらに固定N%は半導体（高ATR）だと誤検知する。**着火判定は ATR比**で行う。

### 3レイヤー構成（ロング＝買い方の追証）

**① 燃料（静的・急落前から分かる「予備軍」）**
| 条件 | フィールド | 閾値の目安 |
|---|---|---|
| 信用倍率が高い | `margin.ratio` | おおむね > 3（買い長） |
| 買い残がWoWで急増 | `margin.long_chg` | 直近で大きくプラス（高値掴みが積み上がった） |
| 直近まで含み益圏 | `daily.ma25_dev_pct` | 直近までプラス〜小幅 → これから含み損に転落する余地 |

→ 3つ揃うほど「投げ燃料」が厚い。**long_chg急増が最も効く**（新規の高値掴み直後の急落が一番投げる）。

**② 着火（動的・トリガー）**
| 条件 | フィールド | 閾値の目安 |
|---|---|---|
| 異常下落 | `change_pct` を `daily.atr_pct` で割る | **下落幅 / ATR% ≧ 2.0**（ATRの2倍超の下げ＝異常） |
| 平均建値割れ | `daily.close` vs `ma25`（`ma25_dev_pct` 符号反転） | MA25を**下抜け**＝信用買い方の平均建値割れの目安 |
| ボラ急騰 | `daily.atr_vs_baseline` | 急拡大＝追証ライン到達が速い |

→ 固定N%でなく **`下落幅 ÷ atr_pct ≧ 2.0`** を使う。半導体の平常ボラを自動で吸収する。

**③ 投げ尽くし（出口・買い場確定）**
| 条件 | フィールド | 閾値の目安 |
|---|---|---|
| 出来高急増 | `daily.vol_x_20d` | **> 3.0**（平常の3倍超） |
| 売られすぎ | `daily.rsi_14` | < 30（できれば < 25） |
| 下ヒゲ | `prices.change_pct` の戻り | 安値から戻して引ける＝投げ吸収 |

**追証期日効果**: 追証は発生から数営業日で強制決済 → **急落から2〜3営業日後の寄り〜前場**に最後の投げが出やすく、そこが底になりやすい。

### スコア式（イメージ）
```
fuel  = (ratio高) + (long_chg急増) + (ma25_dev 直近プラス)        # 0〜3
fire  = (下落幅/atr_pct ≧ 2.0) + (ma25下抜け) + (atr_vs_baseline急拡大)  # 0〜3
exhaust = (vol_x_20d>3) + (rsi_14<30) + (下ヒゲ)                  # 0〜3

判定:
  fuel高 × fire高 かつ exhaust低  → 「これから投げが出る」= まだ買わない / 順張りショート可
  fuel高 × fire高 かつ exhaust高  → 「投げ尽くし」= リバ買いの好機
  fuel低                          → ただの下落。手出し無用
```

### ショート側 — 2パターンを区別する（混同注意）

**A. 追証売りに便乗する順張りショート（ロングの①②と同じ）**
燃料が溜まった銘柄が着火した瞬間に空売り、③の投げ尽くしでカバー。買い場の手前を取る。
滞在は短時間（数時間〜1日）。投げ尽くしで買い戻し損ねると③以降の反発で踏まれる。

**B. 売り方の追証＝踏み上げ（ロングの完全な鏡像）← 「ショートのパターン」の本命**
信用**売り残**が厚い銘柄が逆行高 → 売り方が含み損 → 強制買い戻しで急騰。符号を反転するだけ:

| レイヤー | ロング（買い方の追証） | ショート（売り方の追証＝踏み上げ） |
|---|---|---|
| 燃料 | `ratio`高 ×`long_chg`増 ×`ma25_dev`＋ | `ratio`**低**（売り長）×`short_chg`増 ×`ma25_dev`**−** |
| 着火 | 下落幅/atr ≧2 × `ma25`**下**抜け | 上昇幅/atr ≧2 × `ma25`**上**抜け |
| 出尽くし | `vol_x_20d`>3 ×`rsi_14`<30 × 下ヒゲ | `vol_x_20d`>3 ×`rsi_14`>70 × 上ヒゲ |
| 取り方 | 投げ尽くしを**買う** | 踏み上げ過熱を**戻り売り** |

→ **買い方の追証と売り方の追証は同一フレームの符号違い**。1つのスコアで `direction = long/short` を切り替えて両判定できる。

### この設計の限界（取れないデータ）
- `回転日数`・`逆日歩`・信用期日の警告レベルは取得不可 → 切迫度は `long_chg`/`short_chg`（WoW）＋乖離率で代用。
- 追証の実発生は口座ごと → 価格・出来高・信用残からの**推定**にとどまる。よって「投げ尽くし確認後に動く」を徹底し、着火だけで逆張り突入しない。

## 2. 踏み上げ（強制買い戻し）

### メカニズム
信用売り残が厚い銘柄が逆行高 → 売り方が含み損 → 買い戻し（カバー）が買いを呼ぶ→ さらに踏み上げ。

### 取れるデータ
| シグナル | フィールド | 解釈 |
|---|---|---|
| 売り残が厚い / 倍率低い | `margin.short_qty`, `margin.ratio`（1倍割れ＝売り長） | カバー燃料が多い |
| 売り残が急増した直後の反発 | `margin.short_chg` | 新規空売りの直後に上抜けると踏みやすい |
| 上放れ | `ma5_dev_pct`, `vol_x_20d`, `rsi_14` | 出来高増の上抜けで点火 |

### 狙い方
- **信用倍率が低い（売り長）**銘柄が、好材料 or SOX急騰で上抜けたら踏み上げ初動を買う。
- 逆に、踏み上げで`rsi_14`が過熱しきったら**戻り売り**（カバー一巡後の反落を取る）。
- 制度上の引き金（逆日歩発生）はデータで見えないので、価格と売り残でしか判断できない点に留意。

## 3. インデックス/ETFリバランス強制フロー

### メカニズム
指数の定期入替・比率調整では、インデックスファンドが**当日引けに成行で機械的に売買**する。需要が一時的に集中して価格が歪む。

### 取れるデータ
- `event_context` に「**指数リバランス（月末営業日の窓）**」が出る。
- watchlist 半導体は日経平均・TOPIX寄与度が大きい銘柄が多く、リバランスの影響を受けやすい。

### 狙い方
1. `event_context` がリバランス窓を示したら、対象になりそうな銘柄を数日前に仕込み、**当日引けの強制買いに渡す**。
2. リバランス通過後は反動が出やすい → 翌日の戻り/反落も取れる。
3. ※具体的な採用・除外・比率変更の発表はこのシステム外（指数公式リリース）。`context_body` に手で書いておくと judge が拾える。

## 4. SQ・オプション期日（ピン留めと反動）

### メカニズム
SQ週は大口OIのある権利行使価格に株価が**張り付き（ピン留め）**やすく、SQ通過後に溜まったエネルギーが**一方向に解放**される。

### 取れるデータ
- `event_context`: 「日本SQ週（メジャー/マイナー）」「日本SQ明け」「米メジャーSQ週/明け」
- `market_phase` で当日の時間帯

### 狙い方
- **SQ週**は値動きが鈍る/不自然な張り付きを警戒 → 無理に逆張りしない。
- **SQ明け**の寄りで出た方向（張り付き解放の向き）に乗る。
- 米メジャーSQ → 日本の半導体は翌営業日にギャップで反応しやすい（`premarket.sox_change_pct`と合わせて読む）。

## 5. 地合い連鎖（SOX → 日本半導体の強制反応）

### メカニズム
日本の半導体は米SOX/NASDAQの**寄りギャップに機械的に連動**する。アルゴ・先物裁定が前夜の米国を即座に織り込む＝これも一種の強制フロー。

### 取れるデータ
- `premarket.sox_change_pct` / `nasdaq_change_pct` / `nikkei_futures`
- `sectors[].rel_strength_pct`（セクター内の相対強度）, `vol_ratio`

### 狙い方
- SOX急変の翌日寄りのギャップは「織り込み済み」になりやすい → **寄り天/寄り底の反動**を狙う。
- 同じSOX下落でも `rel_strength_pct` が高い銘柄＝**売られにくい本命**、低い銘柄＝**真っ先に投げが出る弱い手**。1の追証狙いと組み合わせると精度が上がる。

## 6. 実装に進む場合の優先度（参考）

今回はアイデア整理のみだが、もしスキルに組み込むなら効果順:

1. **追証警戒スコア**を signal-judge / crash-scenario に追加（margin.ratio × long_chg × ma25_dev × vol_x_20d）。取れるデータだけで作れて、半導体watchlistに最も効く。
2. **踏み上げ初動**フラグ（ratio低 × short_chg増 × 上放れ）。
3. **event_context の強制フロー解釈**を market-check に明文化（リバランス窓・SQ明けの売買可否）。

### このシステムでは取れない＝判断に組み込めないもの
- 回転日数 / 逆日歩 / 信用期日の警告レベル
- 指数採用・除外の確定情報（手で context に書く必要あり）
- オプションのOI分布（ピン留め水準の特定は不可、SQ週という粗い粒度まで）
